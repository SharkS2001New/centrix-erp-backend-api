## What the user saw

Generic error, no detail. Source: `app/Support/ApiErrorPresenter.php:77`:

```php
return [
    'message' => "An error occurred in {$module}. Please report this to your system administrator.",
    'code' => 'server_error',
    'module' => $module,
    'expose_detail' => false,
];
```

For paths under `api/v1/auth/*`, `moduleLabelForPath` returns `"Auth"`, which
produced the exact string users reported. `shouldExposeDetail` is `true` only
for `is_super_admin`, so regular users never saw the underlying PHP error.

## What actually broke

Login at `AuthController::login` calls `respondWithAuthSession` →
`ErpCapabilitiesController::resolveForUser` →
`UserPermissionService::permissionMapForUser` →
`UserPermissionService::directPermissionMapForUser` →
`UserPermissionService::roleAssignedPermissionIds` (line 87):

```php
public function roleAssignedPermissionIds(User $user): array
{
    return $this->rememberRequest('role_assigned_permission_ids.'.$user->id, function () use ($user) {
        …
    });
}
```

The merged tree had the `$this->rememberRequest(...)` wrapper on 5 methods on
this class but no `rememberRequest()` method body anywhere. First call on
every login trapped as `Error: Call to undefined method`, bubbled up the
Laravel exception pipeline, hit `bootstrap/app.php:227`
`ApiErrorPresenter::userMessage(...)`, and returned 500 with the generic
"Auth" message.

### Secondary noise

The `log channel=stderr` formatter class is misconfigured on this image
(`MonologFormatterJsonFormatter` does not exist). Every logged error then
raised a second `BindingResolutionException`, writing *two* stack traces to
`laravel.log` per request. This did not cause the outage but made the log
noisier and should be cleaned up separately.

## Fix chain

- **Teammate**: `419a7a9f` — "fix(auth): restore UserPermissionService rememberRequest after bad main merge". Added the method using `request()->attributes` as the per-request store (already request-scoped by Laravel).
- **Me (broken)**: `5e9b3674` — same intent, different implementation (in-instance array cache + `scoped` container binding for `UserPermissionService`). Rebased on `419a7a9f` without noticing the method had already been restored. Result: two `rememberRequest` method bodies in the same class → `Cannot redeclare` fatal.
- **Me (final)**: `975a858c` — dropped the duplicate method, `$requestCache` property, `flushRequestCache()`, and the `UserPermissionService` scoped binding in `AppServiceProvider`. Kept the teammate's upstream implementation only.

## Why this was invisible pre-merge

- Static CI did not run `php -l` (or any class-load check) against all app files, so a call to an undefined method on an already-loaded class is a runtime trap, not a parse error.
- No test covered the specific `ErpCapabilitiesController::resolveForUser` → `UserPermissionService::permissionMapForUser` path end-to-end on this branch.
- The author's own session was super-admin, so when they hit the error path locally `ApiErrorPresenter` returned the real detail — easy to overlook or assume was already fixed.
- The audit-logger call added to the login path in the same merge also looked suspicious during static review and absorbed early attention.

## Why the two-commit fix chain happened

Two engineers raced on the same file. `git pull --rebase` reported no conflict because each edit added a new method at a different line; PHP's "same method name twice" is not something git detects as a textual conflict. Only the deployed boot surfaced it.

## Lessons / follow-ups

1. **Boot-time smoke test in CI.** `php artisan route:list` (or any command that boots the framework) would have caught both the undefined-method and redeclare errors in CI before the image ever shipped. File a task to add this to `.github/workflows/ci.yml`.
2. **`ApiErrorPresenter` should log the detail even when it hides it.** The current log already contains the stack trace, but the `code` returned to clients is `server_error` with no incident ID surfaced to non-super-admin users unless `issue_report_id` is set. Confirm that path is always set and surface it in the UI.
3. **`log channel=stderr` formatter.** `MonologFormatterJsonFormatter` is not a real class; whatever config produces that string needs fixing. Every single error currently writes two stacks.
4. **Rebase discipline on hotfixes.** After `git pull --rebase`, always `grep -c "function <methodName>"` on any file you edited before pushing; PHP has no linter-level `duplicate-definition` detector in our pipeline today.
5. **Super-admin vs. regular-user error paths diverge too much.** Consider surfacing a correlation ID to regular users so field reports map 1:1 to a stack trace in `laravel.log`.
